---
title: "Glossary"
description: "Key terms used in the ATH protocol."
---

| Term | Definition |
|------|-----------|
| **Agent** | An AI-powered software entity that acts on behalf of a user to interact with external services. |
| **Agent Attestation** | A signed ES256 JWT that proves an agent's identity. Includes `iss`, `sub`, `aud`, `jti`, and timestamp claims. |
| **Agent Identity Document** | A JSON document published at the agent's `agent_id` URL, containing the agent's name, developer info, and public key. |
| **`agent_id`** | The canonical HTTPS URL identifying an agent (e.g., `https://agent.example/.well-known/agent.json`). |
| **App-Side Authorization** | Phase A of ATH — the service or gateway approves an agent for specific providers and scopes. |
| **ATH** | Agent Trust Handshake — an open protocol for establishing trusted connections between AI agents and external services, building on OAuth 2.0. |
| **`ath_session_id`** | A server-issued identifier tracking an in-progress authorization session. Short-lived (10 min) and single-use. |
| **ATH Token** | An opaque access token issued by the ATH server, bound to a specific agent, user, provider, and scope set. |
| **`client_id` / `client_secret`** | Credentials issued during agent registration, used for token exchange and revocation. |
| **Discovery Document** | A JSON document at `/.well-known/ath.json` (gateway) or `/.well-known/ath-app.json` (native) describing available providers and configuration. |
| **Effective Scopes** | The set of permissions actually granted — computed as the intersection of agent-approved, user-consented, and requested scopes. |
| **ES256** | ECDSA using the P-256 curve and SHA-256 hash — the required signing algorithm for ATH attestations. |
| **Gateway** | A trust broker that mediates between agents and upstream OAuth services. Agents talk ATH to the gateway; the gateway talks OAuth to providers. |
| **JTI (JWT ID)** | A unique identifier in each attestation JWT, used to prevent replay attacks. |
| **Native Mode** | A deployment model where the service implements ATH endpoints directly (no gateway intermediary). |
| **OAuth 2.0** | An authorization framework (RFC 6749) for delegated access. ATH extends OAuth with agent identity and two-axis authorization. |
| **PKCE** | Proof Key for Code Exchange (RFC 7636) — prevents authorization code interception. Required by ATH. |
| **Phase A** | App-side authorization — the server evaluates whether to approve the agent for requested scopes. |
| **Phase B** | User-side authorization — the end user consents to the agent acting on their behalf via OAuth. |
| **Provider** | An external service accessible through the gateway (e.g., GitHub, Google Calendar). |
| **Proxy** | The gateway endpoint (`/ath/proxy/{provider}/{path}`) that forwards agent requests to upstream APIs using stored provider tokens. |
| **Scope** | A string representing a specific permission (e.g., `read:user`, `repo`, `calendar.readonly`). |
| **Scope Intersection** | The formula `Effective = Agent-Approved ∩ User-Consented ∩ Requested` used to compute granted permissions. |
| **Tenant** | A gateway user who owns agent registrations and tokens. Each tenant's data is isolated. |
| **User-Side Authorization** | Phase B of ATH — the end user grants consent via standard OAuth. |
